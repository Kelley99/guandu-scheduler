## 官渡名单系统 - 问题分析与修复计划

### 用户报告的三个问题
1. **正式/候补混淆** — 候补人员被分配到正式队伍中
2. **任务内容丢失** — 导出的Excel表格中各时间段的分工任务内容没有了
3. **候补行丢失** — 导出的Excel表格中没有了候补人员名单和分工的那一行

### 根因分析
- `parse_guandu_xlsx` 函数读错列：当前读 C/D 列，实际人名在 **J 列（index 9）**
- xlsx 解析函数只返回 `(members, bench)`，**没有提取 teams_data**，导致任务信息丢失
- `.md` 文件的解析函数 `parse_guandu_table` 正确构建了 teams_data（含任务），但 xlsx 没有
- 上传 xlsx 时，`teams_data` 始终为空 `{}`，导出时自然没有任务内容

### xlsx 文件实际结构（已通过 openpyxl 验证）
```
列结构：
- A (0): "1队" / "2队" / "替补" 等标识
- B (1): 队长名字
- C (2): A/B 分组标记
- I (8): 行号（1-24 为正式成员，>=25 为候补）
- J (9): 成员名字（主要人名列）
- E-H (4-7): 任务内容（0-10分钟、10-20分钟、20分钟以后）
```

### 修复方案
需要重写 `parse_guandu_xlsx` 函数：
1. 返回 `(members, bench, teams_data)` 三元组（与 md 解析保持一致）
2. 从 J 列（index 9）正确提取成员名字
3. 根据行号（I 列）或 "替补" 标识区分正式成员和候补
4. 从 E-H 列提取任务内容到 teams_data
5. 更新 `upload_guandu` 端点，正确处理 xlsx 的三元组返回值
6. 确保导出 Excel 时包含候补行和任务内容

### 关键代码位置
- `parse_guandu_xlsx` 函数：app.py 约 862-941 行
- `parse_guandu_table` 函数（参考实现）：app.py 约 115 行开始
- `upload_guandu` 端点：app.py 约 1300+ 行
- 导出端点：app.py 约 1400+ 行

### 状态
正在实施修复中，准备重写 `parse_guandu_xlsx` 函数。
