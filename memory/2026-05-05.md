## 17:17 导出Excel tuple index out of range 修复

### 问题
用户点击「导出Excel」按钮后报错：`tuple index out of range`。

### 根因
`/api/export` 端点的 row 索引硬编码与数据库 schema 不一致（与 `/api/list` 同样的问题）：
- 代码用 `row[15]` 读 `infantry_grade`，但 DB 只有 14 列
- ALTER TABLE 添加的列（march_capacity, grades, alliance）附在末尾，但代码的 hardcoded 索引没有相应调整

### 修复
`/api/export` 改用 `PRAGMA table_info(attributes)` 动态获取实际列名，按列名映射替代 hardcoded 索引：
```python
cursor.execute('PRAGMA table_info(attributes)')
cols = [col[1] for col in cursor.fetchall()]
...
row_dict = dict(zip(cols, row))
ws.append([..., row_dict.get('infantry_grade', ''), ...])
```

```python
cursor.execute('PRAGMA table_info(attributes)')
cols = [col[1] for col in cursor.fetchall()]
...
row_dict = dict(zip(cols, row))
ws.append([..., row_dict.get('infantry_grade', ''), ...])
```

## 23:45 图1六维属性OCR识别修复

### 问题
用户通过调试OCR(图1)提供了原始OCR文本，发现六维属性值全部未识别到。

### 根因
OCR文本格式不固定：
- 有的属性名和数值在同一行：`步兵攻击力794.30%`
- 有的属性名单独一行，数值在下一行：`步兵防御力` → 下一行 `889.12%`
- 每个属性名出现两次（如第10行和第12行都是`步兵防御力`），第二次跟的`86%`是基础值
- **需要的是带小数的总值**（如889.12%），不是整数基础值（如86%）

旧代码用全文正则匹配，会被第一个出现的标签行后的`86%`干扰。

### 修复（parse_attribute_image）
重写六维属性提取逻辑：
1. 遍历OCR文本行数组，找含属性名关键词的行
2. 如果同行有小数百分比（`XXX.XX%`），直接取
3. 否则检查后续2行，优先取带小数的百分比值
4. 跳过纯整数百分比（如`86%`，那是基础值）
