### attribute_collector 项目 bug 分析

**问题根因已定位（待修复）**：

`app.py` 中存在一个持续多处的 bug：**后端只提取/存储/返回 6 个六维属性，缺少 3 个关键字段**。

缺失字段：`infantry_attack`（步兵攻击力）、`cavalry_defense`（骑兵防御力）、`archer_defense`（弓兵防御力）

实际游戏六维是 **9 个**（3兵种 × 攻防破坏），但代码里只有 6 个。

受影响的代码位置：
1. `attr_labels` 列表（OCR 提取）- 缺少 3 个字段名
2. SQLite `INSERT` 语句 - 缺少 3 个字段
3. `/api/list` API - 缺少 3 个字段的列定义和返回
4. `/api/export` Excel导出 - 缺少 3 个字段
5. `templates/index.html` 前端表单 - 只显示了 6 个字段的输入框，缺少 3 个

**OCR 提取逻辑本身没问题**，完整截图扔进去能正确提取全部 9 个值。问题是数据流从 OCR 提取之后就在多处被截断了。

**修复方案**（已在分析中，session 紧凑前正在执行）：
- `attr_labels` 增加 3 个字段名
- INSERT 语句加字段
- list API 的 columns 列表加字段
- export 的 g() 函数加字段
- 前端表单加 3 个输入框
- DB 无需改表，列已存在

### 技术经验补充

- 属性录入系统的截图格式：图片1=集结属性截图（含9个字段），图片2=六维总览截图（含5个数值）
- OCR 识别：数字基本可靠，文字部分（名字/同盟/等级）需手动二次确认

1. `attr_labels` 添加 `('infantry_hp', '步兵生命值')`（在 defense 和 break 之间）
2. UPDATE SQL 添加 `infantry_hp = ?` 和 `data['infantry_hp']`
3. INSERT SQL 添加 `infantry_hp` 列和参数
4. 导出 headers 添加 `'步兵生命值'`
5. 导出 `g()` 调用添加 `g(row, 'infantry_hp')`

**templates/index.html**：
1. `formData` ref 初始值添加 `infantry_hp: 0`
2. HTML 添加"步兵生命值"输入框（在步兵防御力和步兵破坏力之间）
3. `total6d` computed 添加 `parseFloat(formData.value.infantry_hp || 0)`
4. `resetForm` 添加 `infantry_hp: 0`
