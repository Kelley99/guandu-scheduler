## parse_stats_xlsx 成员表格式 Bug 修复（2026-05-14 09:36 UTC）

### 问题
Kelley 发来 `凌霄成员表 2026,05.10.xlsx` 测试，发现上传后返回空数据。

### 根因
`parse_stats_xlsx` 在读取 xlsx 时，第一行是工作表标题（`'表格 1'`），而非实际列头（`'成员名称', '阶级', '火炉等级', '战力'...`）。代码错误地把标题行当作列头扫描，找不到 `战力` 列，导致整表解析失败。

### 修复 (app.py 第 897 行 `parse_stats_xlsx` 函数)
在 `header` 扫描后检测：如果整个 header 行里没有 `战力` 列且行首是标题类内容（'表格', 'Sheet', '工作表'），则跳过该行，用下一行作为真正的 header。

```python
# 如果没找到战力列且当前行像是标题行（第一列是'表格1'等），跳过它
if power_idx is None and row_count == 1:
    if header[0] and ('表格' in str(header[0]) or 'Sheet' in str(header[0])):
        header = None
        continue
```

### 凌霄成员表格式
- 列结构：A索引 B成员名称 C阶级 D火炉等级 E战力 F周功勋 G总功勋 H周捐献
- 特点：**无 hp/total 列**，只有姓名+战力
- 数据：100人，战力范围 3亿~5.5亿
- 解析后 sort_fields 只有 `power`（战力）可用

## A/B组逻辑修正（2026-05-14 04:20 UTC）

### Kelley 的修正
- **不再强制偶数**: A/B组模式下，每队人数可以是奇数（如9人），不需要调整
- **队长单独算**: 每队 = 1队长 + A组 + B组，队长不参与A/B分配
- **A/B组不需均分**: 可以 A组4人 / B组4人，也可以 A组5人 / B组3人

### 队形数据结构调整
```javascript
formation = {
  teamCount: 6,
  teamSize: 9,        // 总人数，不强制偶数
  hasAB: true,
  groupASize: 4,      // A组人数（可调），B组 = teamSize - 1 - groupASize
  tasks: {
    '0-10': [],       // 队长+A组任务（相同）
    '10-20': [],
    '20+': [],
    '0-10-b': [],     // B组任务（可与A组不同）
    '10-20-b': [],
    '20+-b': []
  }
}
```

### 前端UI改动 (formation.html)
- 删除 `abWarning` 和强制偶数逻辑
- 新增 A/B组人数分配滑块：拖动调整A组人数，B组自动计算
- 时间轴配置：每个时间段显示"队长+A组"和"B组"两个下拉，B组有"同A组"快捷选项
- 预览表格：每队3行 → 👑队长(1人) / 🟢A组(n人) / 🔵B组(m人)
- 统计数据增加：队长数、队员数单独显示
- 预设队形增加 `groupASize` 字段

### 经典6队×9人示例
- 6队长 + 24人A组 + 24人B组 = 54人总
- A/B分配可调：如 A组4人/B组4人，或 A组5人/B组3人

### 再次修正：每队人数独立可变（2026-05-14 04:20 UTC）

Kelley 再次指出理解错误：

```javascript
formation = {

  ]
}
```

**新UI设计**：
- 团总人数输入（默认30）
- 队数选择（5-9）
- 统计栏：已分配/待分配/队长/队员，配平提示
- 队伍列表：每队独立配置"总人数/队长数/A组人数"，B组自动算
- 均分填充按钮：将30人平均分配到各队
- 每队独立任务配置（队长+A同任务，B组可差异化）
