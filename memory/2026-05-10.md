## 考勤系统完整重建完成（20:28 UTC+8）

### 后端 12 个新 API（app.py）
1. `GET /api/att/members` — 获取成员列表
2. `POST /api/att/members/import` — 从属性表导入成员
3. `POST /api/att/members` — 手动添加成员
4. `DELETE /api/att/members/<id>` — 删除成员
5. `POST /api/att/reports` — 创建战报（选军团+日期+OCR截图）
6. `GET /api/att/reports` — 获取战报列表
7. `GET /api/att/reports/<id>` — 获取战报详情（含考勤明细）
8. `DELETE /api/att/reports/<id>` — 删除战报
9. `GET /api/att/reports/<id>/detail` — 获取考勤明细
10. `PUT /api/att/reports/<id>/detail/<did>` — 修改考勤状态（四态切换）
11. `GET /api/att/export/<id>` — 导出战报Excel
12. `POST /api/att/ocr` — OCR识别积分榜截图

### 数据库（gc_attendance.db）
- `att_members` 表：id, name, power, source, created_at
- `att_reports` 表：id, group_name, report_date, total, present, absent, leave, sub, created_at
- `att_detail` 表：id, report_id, member_id, name, status (present/absent/leave/substitute)

### 前端 3 个 Tab（考勤管理）
- 📋 成员名单 — 从属性表一键导入，手动添加/删除
- 📊 战报记录 — 列表展示各状态人数，查看/导出/删除
- ➕ 创建战报 — 选军团+日期+上传积分榜截图OCR识别 → 自动生成考勤

### 考勤逻辑
- OCR识别名字 → 在成员名单中 → 标记"出席"
- 在名单中但不在OCR结果中 → 标记"缺席"
- 不在名单中但OCR识别到 → 标记"候补上场"
- 管理员可手动切换四态：出席 ✅ / 缺席 ❌ / 请假 ⚠️ / 候补上场 🔵
