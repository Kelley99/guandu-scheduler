## 2026-05-04 14:52 (Asia/Shanghai)

### OCR 首次加载问题修复
- **问题**：用户点击 OCR 按钮无响应，原因是 EasyOCR 首次调用时需下载检测模型（几百MB），导致请求超时
- **排查过程**：
  1. 前端检查：`triggerOcrUpload` 和 `doOcrUpload` 逻辑正确
  2. 后端检查：Flask 日志显示 "Downloading detection model..." 卡住
  3. 定位：`get_ocr_reader()` 懒加载在首次请求时触发下载，阻塞请求
- **解决方案**：在 `app.py` 的 `if __name__ == '__main__':` 块中，`app.run()` 之前添加预加载调用：
  ```python
  print('[启动] 预加载OCR模型...')
  try:
      get_ocr_reader()
      print('[启动] OCR模型加载成功')
  except Exception as e:
      print(f'[启动] OCR模型加载失败: {e}')
  ```
- **效果**：模型在服务启动时下载，下载完成后缓存到 `~/.EasyOCR/`，后续启动秒加载
- **用户指引**：首次启动需等待日志出现 "OCR模型加载成功" 后再使用 OCR 功能

  ```python
  def preload_ocr_async():

  threading.Thread(target=preload_ocr_async, daemon=True).start()
  ```

### OCR 预加载阻塞启动问题修复
- **问题**：预加载 OCR 模型时，因模型下载时间长导致 Flask 启动阻塞，进程可能超时退出
- **解决方案**：将 OCR 预加载改为后台线程非阻塞方式：
  ```python
  def preload_ocr_async():
      time.sleep(2)  # 等Flask先启动
      try:
          get_ocr_reader()
          print('[OCR] OCR模型加载成功，可以使用')
      except Exception as e:
          print(f'[OCR] OCR模型加载失败: {e}')

  threading.Thread(target=preload_ocr_async, daemon=True).start()
  ```
- **效果**：Flask 立即启动并响应请求，OCR 模型在后台加载，日志显示 `[OCR] OCR模型加载成功，可以使用` 后即可使用 OCR 功能

  ```python
  def preload_ocr_async():

  threading.Thread(target=preload_ocr_async, daemon=True).start()
  ```

- **问题**：用户点击 OCR 按钮无响应，原因是 EasyOCR 首次调用时需下载检测模型（几百MB），导致请求超时

  2. 后端检查：Flask 日志显示 "Downloading detection model..." 卡住
  3. 定位：`get_ocr_reader()` 懒加载在首次请求时触发下载，阻塞请求
- **解决方案**：在 `app.py` 的 `if __name__ == '__main__':` 块中，`app.run()` 之前添加预加载调用：
  ```python
  print('[启动] 预加载OCR模型...')
  try:
      get_ocr_reader()
      print('[启动] OCR模型加载成功')
  except Exception as e:
      print(f'[启动] OCR模型加载失败: {e}')
  ```
- **效果**：模型在服务启动时下载，下载完成后缓存到 `~/.EasyOCR/`，后续启动秒加载
- **用户指引**：首次启动需等待日志出现 "OCR模型加载成功" 后再使用 OCR 功能

## 2026-05-04 18:52 (Asia/Shanghai)

### OCR 预加载阻塞启动问题修复
- **问题**：预加载 OCR 模型时，因模型下载时间长导致 Flask 启动阻塞，进程可能超时退出
- **解决方案**：将 OCR 预加载改为后台线程非阻塞方式：
  ```python
  def preload_ocr_async():
      time.sleep(2)  # 等Flask先启动
      try:
          get_ocr_reader()
          print('[OCR] OCR模型加载成功，可以使用')
      except Exception as e:
          print(f'[OCR] OCR模型加载失败: {e}')

  threading.Thread(target=preload_ocr_async, daemon=True).start()
  ```
- **效果**：Flask 立即启动并响应请求，OCR 模型在后台加载，日志显示 `[OCR] OCR模型加载成功，可以使用` 后即可使用 OCR 功能

### Flask+Vue 分隔符冲突问题修复（属性收集工具）

- **问题现象**：页面上错误提示显示为 `[[errorMsg]]` 而非实际错误内容
- **问题定位**：
  1. 项目使用 Vue 3，尝试通过 `app.config.delimiters = ['[[', ']]']` 修改分隔符
  2. 但 Vue 3 的分隔符配置方式不同于 Vue 2，`delimiters` 配置未生效
  3. 导致 `[[errorMsg]]` 仍被当作普通文本输出，未被 Vue 解析
- **解决方案**：
  1. 恢复 Vue 默认分隔符 `{{ }}`
  2. 在 Jinja2 模板中，将包含 Vue 模板语法的区块用 `{% raw %}...{% endraw %}` 包裹
  3. Jinja2 会忽略 `{% raw %}` 区块内的内容，直接原样输出，让 Vue 在浏览器端处理
- **修改文件**：`~/Desktop/kelley_work/attribute_collector/templates/index.html`
- **修改内容**：
  - 移除 `app.config.delimiters = ['[[', ']]']` 配置
  - 在 `<div id="app">` 内部所有 Vue 模板语法区块外包裹 `{% raw %}...{% endraw %}`
- **服务状态**：Flask 已重启（端口5002）
- **关键经验**：
  - **Flask+Vue 最佳实践**：Vue 用默认 `{{ }}` 分隔符 + Jinja2 用 `{% raw %}` 包裹 Vue 模板区块
  - 不要试图修改 Vue 分隔符（Vue 3 配置方式不直观且易失效）
  - `{% raw %}` 让 Jinja2 原样输出，Vue 在浏览器端接管解析
